# vibekit: полное удаление VibeMon и VibeNotif + пас по практикам Claude Code — design (v1.7.0)

Date: 2026-09-02
Status: DRAFT (ревизия 4 — объём уточнён пользователем, план прошёл ревью Codex)
Target release: v1.7.0

## Цель

1. **Убрать VibeMon и VibeNotif из репозитория целиком.** После релиза vibekit
   не поставляет ни одного хука.
2. **Вычистить их с локальных машин отдельным скриптом**, который пользователь
   запускает сам. В установщик миграция не встраивается.
3. **Взять у `github.com/nalbam/dotfiles` только то, что касается конфигурации
   Claude Code.** Скиллы, шелл-дотфайлы и AWS-контент не берём.

## Жёсткое ограничение

Каталоги `hooks` и файлы конфигурации хуков **общие**. Удалять их целиком
нельзя. Фактическая картина на машине разработчика:

```
~/.claude/hooks/          caveman-*.js ×5, package.json   ← чужое, не трогать
                          vibenotif.py, vibemon.py        ← наше, удалить

~/.claude/settings.json   PreToolUse: [ vibenotif , rtk hook claude ]
                                        ↑ убрать      ↑ сохранить

~/.cursor/hooks.json      preToolUse: [ vibenotif , impeccable hook ]
                                        ↑ убрать      ↑ сохранить
```

Поэтому чистка работает **по отдельным записям**, а не по файлам и каталогам.

## Что удаляется само, а что руками

`prune_target` (lib/sync.sh:146) удаляет только файлы, перечисленные в манифесте
предыдущей синхронизации, и никогда не трогает каталоги и чужие файлы. Манифесты
сейчас содержат `hooks/vibenotif.py` для claude, cursor и kiro.

Значит, как только репозиторий перестанет поставлять эти три файла, ближайший
`./install.sh` **сам** удалит их с машины, не задев хуки Caveman.

Руками остаётся то, до чего prune не дотягивается:

| Артефакт | Кто убирает |
|---|---|
| `hooks/vibenotif.py` в трёх целях | prune, автоматически |
| записи хуков в `~/.claude/settings.json` | скрипт чистки |
| записи хуков в `~/.cursor/hooks.json` | скрипт чистки |
| хуки и описание в `~/.kiro/agents/default.json` | скрипт чистки |
| `~/.claude/hooks/vibemon.py`, `~/.kiro/hooks/vibemon.py` (старьё, не в манифесте) | скрипт чистки |
| `~/.vibenotif/config.json`, `cache/statusline.json` | скрипт чистки |
| LaunchAgent, процесс, npx-кэш, данные приложения VibeMon | скрипт чистки |

`~/.vibenotif/cache/token_window.json` скрипт **сохраняет**: его читает строка
состояния для таймера сброса токенов. Каталог уйдёт вместе с переносом этого
пути на Шаге 1.

Секретов в `~/.vibenotif/config.json` нет — там лежит только
`{"auto_launch": false}`. Отзывать нечего.

## Скрипт чистки

`scripts/purge-vibenotif.sh`. По умолчанию ничего не меняет и печатает план;
применяет только с `APPLY=1`. Перед правкой JSON делает резервные копии в
`~/.vibekit-purge-backup-<дата>`. Все пути ограничены `$HOME`. Повторный запуск
безопасен.

Отбор — по вхождению `vibenotif` или `vibemon` в сериализованную запись хука.
Пустые группы и события после этого удаляются, непустые сохраняются со всем
чужим содержимым.

## Решение по statusline.py

`claude/statusline.py` — строка состояния в терминале: модель, ветка, контекст,
стоимость, таймер сброса токенов. С VibeNotif её связывают три нити: чтение
`~/.vibenotif/config.json` (строка 25), переменные `VIBENOTIF_*` (38-47, 62) и
запись кэша `~/.vibenotif/cache/statusline.json` (277-345, 670).

**Рекомендация: строку состояния оставить, нити перерезать.** Кэш убрать
целиком, конфиг перевести на собственные переменные, `token_window.json`
перенести в `~/.claude/`. Константа `VIBE_MONITOR_MAX_PROJECTS` уходит с кэшем.

Альтернатива — удалить `statusline.py` и ключ `statusLine` из настроек. Это
потеря функции, к задаче не относящейся.

## Что берём у nalbam — только Claude Code

1. **CI.** Восемь наборов тестов, ни один не запускается на pull request. Новый
   `.github/workflows/test.yml` с `bash test/run.sh`. Проверку надо сделать
   обязательной в branch protection: `.mergify.yml` мержит по `base=main` плюс
   одно одобрение и сам по себе воротами не является.
2. **Сузить `Bash(*)`.** Сейчас разрешена любая команда, защитой остаётся
   чёрный список, где три записи не работают: `Bash(rm -rf $HOME/*)` сравнивает
   буквальную строку `$HOME`, пара `curl * | sh` обходится через `sh -c`,
   `Bash(chown -R * /:*)` синтаксически неверна. Из-за объединения массивов
   нужна отдельная миграция удаления. То же самое в `cursor/cli-config.json:6`.
3. **Дубли агентов** — восемь пар: architect/system-designer,
   debugger/bug-hunter, builder/build-doctor, refactorer/code-shaper,
   doc-writer/docs-crafter, planner/task-planner, test-writer/spec-writer,
   quality-guard/code-reviewer.
4. **`enabledPlugins` со значением `false`** для ненужных плагинов, иначе
   решение не переживает слияние.

Не берём: их слияние настроек (получатель всегда побеждает), их генератор для
Codex (~30 буквальных замен, молча ломается при переформулировке), `stale.yml`
и `auto-merge.yml`, `Bash(terraform *)` в запретах, а также `defaultMode`,
`effortLevel`, `outputStyle`, `tui`, `theme`, `skillOverrides`.

Скиллы не берём. Облачного контента, пригодного для vibekit, у него нет:
`aws/config` из двух строк, `ssh/config` на один хост, алиасы вокруг aws-vault
и скилл про Next.js на корейском.

## Шаги

### Шаг 0 — CI, отдельным PR, первым

`.github/workflows/test.yml` запускает `bash test/run.sh` на каждый PR.
Отдельная команда для генератора не нужна: `test_codex_agents.sh` уже его
проверяет. Отметить проверку обязательной.

**Проверка:** workflow краснеет на сломанном тесте; PR с красной проверкой не
мержится.

### Шаг 1 — репозиторий без хуков

Удалить `claude/hooks/vibenotif.py`, `cursor/hooks/vibenotif.py`,
`kiro/hooks/vibenotif.py` и `lib/vibemon.sh`. Убрать ключ `hooks` из
`claude/settings.json`. Убрать хуки и упоминание VibeNotif из
`kiro/agents/default.json`. Перерезать нити в `claude/statusline.py`.

Из `install.sh` убрать флаги `-V`, `-M`, `-P`, переменные `VIBENOTIF`,
`VIBEMON`, `VIBEMON_PURGE`, патчер `auto_launch` (675-718), блок отключения
VibeNotif (633-673), подключение `lib/vibemon.sh` (356-365) и все строки
справки. Синхронизацию каталогов не менять: prune уберёт файлы сам.

**Проверка:** `bash -n install.sh`; `python3 -m py_compile claude/statusline.py`;
`grep -rniE 'vibenotif|vibemon|19280' claude cursor kiro codex lib install.sh`
пусто; на песочничном `HOME` синхронизация удаляет три файла хуков и не трогает
посторонние файлы в тех же каталогах.

### Шаг 2 — тесты, в том же PR

Удаление `lib/vibemon.sh` сразу ломает `test_purge_vibemon.sh` и
`test_safe_rm_guard.sh`, поэтому тесты правятся тем же изменением, а не
следующим.

Удалить `test/test_purge_vibemon.sh`, `test/test_safe_rm_guard.sh`,
`test/test_vibenotif_url.sh`. В `test/test_install_bootstrap.sh` перенацелить
I1-I3 на `lib/sync.sh` (подключается так же, install.sh:369), I4 удалить.
Переименовать префикс `vibemon-test.XXXXXX` в `test/helpers.sh:37`. Добавить
проверку, что синхронизация удаляет файл хука и сохраняет соседний чужой файл.

**Проверка:** `bash test/run.sh` зелёный; новый сценарий падает на сегодняшнем
установщике.

### Шаг 3 — документация и релиз, в том же PR

`docs/configuration.md` — 20 упоминаний, раздел уходит, описание строки
состояния остаётся. `CLAUDE.md` — 11 упоминаний, включая таблицу событий и
флаги. `README.md`, `SECURITY.md`. `CHANGELOG.md` — запись `## [1.7.0]` с
разделом Removed и командой чистки. `VERSION`: 1.6.1 → 1.7.0. Перегенерировать
`codex/AGENTS.md` **в режиме записи**, не только `--check`.

**Проверка:** `grep -rniE 'vibenotif|vibemon|19280' --exclude-dir=.git .` даёт
только историю CHANGELOG, этот документ и скрипт чистки; `bash test/run.sh`
зелёный.

### Шаг 4 — права доступа, отдельным PR

Заменить `Bash(*)` перечнем нужных префиксов в `claude/settings.json` и
`cursor/cli-config.json`, починить три нерабочие записи запретов, добавить
миграцию удаления, привести `SECURITY.md` в соответствие.

**Проверка:** на машине, где `Bash(*)` уже стоял, названная команда начинает
спрашивать разрешение, другая названная продолжает работать.

### Шаг 5 — агенты и плагины, отдельными PR

Схлопнуть восемь пар агентов, прижать ненужные плагины значением `false`.

**Проверка:** три названные задачи попадают к тому же агенту, что и раньше.

## Порядок

```
Шаг 0  CI
  ▼
Шаг 1 + 2 + 3   один PR: удаление кода ломает тесты, разрывать нельзя
  ▼
Шаг 4  права доступа (свой PR, вопрос безопасности)
  ▼
Шаг 5  агенты, плагины (свои PR)
```

Codex после каждого шага; следующий раунд перепроверяет исправления
предыдущего, а не верит им на слово.
